# Maintenance Order (Wartungsauftrag)

> Business object: `BSOMaintOrder` (Assembly `gip.mes.maintenance`, Menu: **Maintenance → Maintenance Order**)

## Definition

A **maintenance order** is created by the system from a **maintenance plan** for a
facility or a technical component. It contains the **tasks** (work steps) that the
maintenance operator has to perform, the planned and actual dates, and the
assignments (users, user groups or external companies) responsible for the order.

Maintenance orders are *not* created manually in this app — they are generated by the
maintenance plans. This app is used to **search, execute and complete** them.

## Concepts

| Term | Meaning |
|---|---|
| **Maintenance order** | One execution of a maintenance plan for a facility/component |
| **Maintenance plan** | The periodic/event-based definition from which orders are generated (order is *based on* the plan) |
| **Task** | A work step of the order with planned/actual dates and a state (unfinished → in process → completed) |
| **Assignment** | User, user group or company the order is assigned to |
| **Order state** | *Maintenance needed* → *Maintenance in process* → *Maintenance completed* |
| **Order property** | Value of a component property that is checked/maintained by the order |

## Screen layout

The app consists of a search list (**Explorer**, dockable on the right) and the order
form. The order form has a header area and these tabs:

| Tab / area | Content |
|---|---|
| Header | Component caption, **Order No.**, **Order state**, planned start/duration, actual start/end/duration, created date, live visualisation of the component |
| **Tasks** | Task list (left) and the form of the selected task (right) with **Start Worktask** / **Worktask completed** / **Documentation** buttons |
| **Images** | Media (photos/documents) of the selected task |
| **Properties** (docked right) | Order properties per component property, with *periodical based* / *event based* parameter tabs |
| **Info** | Role assignments of the order (role list/form) |
| **Details** | Comment / free text of the order |

Dialogs:

* **Maintenance Order dialog** — opened via *Show Maintenance Order* or from the
  process visualisation; shows the order and its tasks with the work buttons.
* **Warnings dialog** — shows the alarming components and offers to open the
  corresponding maintenance order.
* **Choose Object dialog** — facility tree and component tree for filtering.

## Searching and filtering orders

1. Enter a search string in the search field of the **Explorer** and click **Search**.
2. Restrict the list with the **Order state** combo box (default: *Maintenance needed*).
3. Click **Choose Object** to filter by a **facility** or a **technical component**;
   confirm with **OK**. **Clear Object** removes the filter again.
4. Use the checkboxes **My tasks**, **My default tasks** or **Outsourced tasks** to
   filter by assignment.
5. Select an order in the list — it becomes the current order and its tasks,
   properties and visualisation are loaded.

## Executing a maintenance task

On the **Tasks** tab (or in the Maintenance Order dialog):

1. Select the task in the task list.
2. Click **Start Worktask** — the task state becomes *in process*, the start date is
   set to now, and the order state becomes *Maintenance in process*. The change is
   saved automatically.
3. Perform the work. The **Documentation** button shows the documentation
   (images/documents) of the task.
4. Click **Worktask completed** — the task state becomes *completed* and the end date
   is set to now. When **all** tasks are completed, the order state becomes
   *Maintenance completed* and the order start/end dates are calculated from the tasks.
5. Enter remarks in the **Comment** field of the task or the order and click **Save**.

**Note:** once the order is completed, the actual start/end dates and the comment of
the order are read-only.

## Editing an order

* Change fields (e.g. actual dates, comment) on the current order and click **Save**.
* **Undo** reverts unsaved changes.
* **Delete** removes the current order **with all its tasks, properties and
  assignments** — only if no other data references it. Always click **Save** afterwards
  to execute the delete in the database.
* **Load** refreshes the current order if another user changed it in the background.

## Opening orders from the process visualisation

* **Show Maintenance** — searches the open orders of a component (first *Maintenance
  needed*, otherwise *Maintenance in process*) and opens the order dialog; if none
  exists an info message is shown.
* **Show Maintenance History** — shows the completed orders of a component.
* **Show Maintenance Warning** — called for alarming components; shows the warnings
  dialog and the matching orders.
* **Navigate to visualisation** — jumps from the order to the process visualisation of
  its component.

## Field reference (order header)

| Field | Description |
|---|---|
| Order No. | Number of the maintenance order (sorted descending in the list) |
| Order state | *Maintenance needed* / *Maintenance in process* / *Maintenance completed* |
| Planned start / Planned duration | From the maintenance plan |
| Start / End / Duration | Actual dates; calculated from the tasks on completion |
| Set date / Set duration | Values set by the maintenance plan |
| Created | Date the order was generated |
| Component | Facility or technical component the order belongs to |
| Interval | Interval of the underlying maintenance plan |
| Comment | Free text (read-only when completed) |

### Task fields

| Field | Description |
|---|---|
| Task name / Task description | Name and description of the work step |
| Task state | Unfinished / in process / completed |
| Planned start / Planned duration | From the maintenance plan |
| Start / End / Duration | Actual values, set by **Start Worktask** / **Worktask completed** |
| Comment | Free text of the task |
